Project Scope & Features

What is Oryn?

A lightweight, self-hosted web mail management platform designed to give organizations full ownership over their email delivery infrastructure.

🎯 Project Purpose & Motivation

• Commercial email providers (Google Workspace, Microsoft 365) are costly and act as closed black boxes with zero local control.

• Oryn provides an independent alternative: users can attach custom domains, configure DNS records, provision multiple mailboxes, and compose/read emails via an intuitive webmail dashboard.

• Academic Objective: Engineer a full-stack system strictly adhering to software engineering tenets: MVC separation, RESTful routing, and asynchronous client integration.

📥

📫
Multi-Account Support
Create and instantly switch between multiple user mailboxes (e.g. team@domain.com).
🌐
Domain & DNS Wizard
Attach custom domains and inspect DNS health (MX, SPF, DKIM, and DMARC).
📊
Live Telemetry
Real-time storage counters, server port indicators, and inbound message counters.

📁 Standard MVC Folders

• src/routes/: Defines URL paths and connects them directly to controller functions.

• src/controllers/: Reads req.body and req.params, performs validation, and sends res.status().json().

• src/models/: Executes queries, persists records, and encapsulates data schemas.

🧰 Dedicated Helpers Folder (src/helpers/)

• Low-level utilities (RFC 5321 SMTP daemon, DNS resolver, storage engine) are strictly isolated.

• Architectural Benefit: Prevents controller bloating and keeps MVC controllers concise, testable, and textbook clean.

Controller & Model Deep Dive

Handling Requests & Managing Data

The controller orchestrates validation and response, while the model manages persistence.

Controller: email.controller.js 
static async sendEmail(req, res) {
  try {
    const { from, to, subject, text } = req.body;

    // 1. Input Validation
    if (!from || !to || !subject) {
      return res.status(400).json({ error: 'Missing required fields' });
    }

    // 2. Call Model to create record
    const newEmail = await EmailModel.create({
      from, to, subject, text, folder: 'sent'
    });

    // 3. Return HTTP 201 Created
    res.status(201).json({ success: true, email: newEmail });
  } catch (err) {
    res.status(500).json({ error: err.message });
  }
}
Model: email.model.js 
// backend/src/models/email.model.js
export class EmailModel {
  // Encapsulates storage & query execution
  static async findAll(filter = {}) {
    const emails = await storage.readAll('emails');
    return emails.filter(e => (!filter.folder || e.folder === filter.folder));
  }

  static async create(data) {
    const record = { id: generateId(), ...data, createdAt: new Date() };
    await storage.insert('emails', record);
    return record;
  }
}
Client Integration

Frontend API Calling (React 19)

How our UI consumes backend endpoints via asynchronous fetch() requests.

frontend/src/components/EmailList.jsx 
import { useState, useEffect } from 'react';

export function EmailList({ currentFolder }) {
  const [emails, setEmails] = useState([]);
  const [loading, setLoading] = useState(true);

  // Call GET /api/emails on load
  useEffect(() => {
    async function fetchEmails() {
      try {
        const res = await fetch(`/api/emails?folder=${currentFolder}`);
        const data = await res.json();
        setEmails(data.emails || []);
      } finally {
        setLoading(false);
      }
    }
    fetchEmails();
  }, [currentFolder]);

  return <div>{emails.map(e => <EmailItem key={e.id} email={e} />)}</div>;
}
1. Asynchronous Fetch & Promises
Frontend calls backend REST routes using native fetch() wrapped in async/await for clean non-blocking flow.
2. Reactive State Synchronization
When emails are dispatched (POST /api/emails/send) or marked read (PATCH /api/emails/:id), React state updates DOM elements instantaneously.
3. Graceful Loading & Error Toasting
Manages spinners during network round-trips and renders floating toast notifications if HTTP 4xx or 5xx responses occur.
