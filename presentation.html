Problem Statement & Objectives

Why Engineer an Autonomous Mail Server?

Modern email is dominated by black-box proprietary providers (Google Workspace, Microsoft 365). Building an in-house MTA unpacks core computer networking fundamentals:

📡 Low-Level Protocols

Direct implementation of RFC 5321 (Simple Mail Transfer Protocol) and RFC 822/2045 MIME multi-part stream handling without third-party wrappers.

🛡️ Email Authentication

Demystifying sender verification via cryptographic headers: SPF (Sender Policy Framework), DKIM digital signatures, and DMARC enforcement policies.

🌐 Network Deliverability

Overcoming real-world ISP port 25 residential blocking through dual-mode intelligent routing: Direct MX resolution with authenticated SMTP Relay failover.

Security & Cryptography

Email Authentication & Spoofing Defense

Authored by Arpit Rajput: automated cryptographic analysis of incoming email headers to detect spoofing and phishing.

🛡️ SPF Analysis

Inspects the Received-SPF header against authorized CIDR ranges. Identifies PASS, SOFTFAIL, and hard FAIL (spoofed envelope sender).

🔑 DKIM Signature

Analyzes DKIM-Signature public key hashes from DNS TXT records to verify body content has not been tampered with in transit.

📜 DMARC Policy

Evaluates header alignment between From and envelope return-paths, surfacing live verification badges in the frontend UI.

// helpers/securityEngine.js export function analyzeSecurityHeaders(headers = {}) { const result = { spf: 'none', dkim: 'none', dmarc: 'none', isSafe: true, warnings: [] }; const receivedSpf = headers['received-spf'] || ''; if (receivedSpf.includes('pass')) result.spf = 'pass'; else if (receivedSpf.includes('fail')) { result.spf = 'fail'; result.isSafe = false; result.warnings.push('SPF validation failed (possible sender address spoofing).'); } return result; }
Outbound Deliverability

Dual-Mode Dispatch & ISP Port 25 Bypass

Delivers emails directly to recipient MX servers, with automatic fallback to authenticated SMTP relay when residential ISPs filter port 25.

Mode 1: Direct MX Resolution

1. Extracts recipient domain (e.g. gmail.com).
2. Resolves DNS MX records via dns.promises.resolveMx.
3. Connects directly to highest-priority exchange on port 25.
4. Ideal for dedicated VPS or static server IPs.

Mode 2: Authenticated SMTP Relay

1. Encrypted TLS tunnel over Port 587.
2. Verified credentials with Brevo, SendGrid, or Mailgun.
3. Automated fallback if direct port 25 handshake times out.
4. Built-in live connection test endpoint (/api/relay/test).

DNS Infrastructure

DNS Configuration & Live Verification

Built-in engine providing step-by-step registrar records and dynamic public IP detection to avoid manual mistakes.

Type A (Host)

Host: mail
Value: 115.244.141.202
Maps mail subdomain to host server public IP.

Type MX (Routing)

Host: @
Value: mail.glennesports.app
Priority: 10
Routes domain mail to our MTA.

Type TXT (SPF)

Host: @
Value: v=spf1 mx a:mail... ~all
Authorizes mail server to send.

Type TXT (DMARC)

Host: _dmarc
Value: v=DMARC1; p=none...
Enforces policy & reporting.

🔍 Live DNS Query Tool (/api/dns/verify)

The system actively queries external DNS root resolvers in real-time, verifying whether the domain's MX records and SPF policy have propagated successfully across the internet.
